# 2026-09-16 改动清单：内核可靠性与体验

## 可用于汇报的概述

本轮完善插件内核的检查与同步机制：修复检查报错却返回成功的问题，同步前先准备全部输出，增加卸载预检查和规则一致性检查，并补齐待办日志类型。通过针对性检查和相同输入的原版/修改版对比验证，配套提供独立体验库。

修改作用于 `lelele240217/vault-wiki`，不向原作者仓库提交修改。

## 验证证据

- 11 个针对性测试方法通过；覆盖失败传播、坏附检返回、晚期标记错误、重复标记、卸载引用、全部投影、只读检查、重复同步、手写区保留及待办日志。
- 六个独立机械演示场景通过。
- 同样的故障输入分别交给原版 `0ead1b3` 和本地修复版 `5b274fe`，已实际复现：错误返回值 0→1；同步失败修改一个文件→零文件变化；todo 日志拒绝→写入成功。
- 虚构会议由 Agent 阅读规则后建立资料卡、知识页和自动索引；检查零错误，有一条新笔记暂无入链的提示。未使用真实会议隐私资料。
- 当前 Agent 的有指导演示，不等于跨平台、跨模型或独立冷启动验证。

## 限制与保留项

- 临时文件替换保障单文件写入，不承诺断电或系统故障时跨文件全部成功或全部回退。
- `audit` 的只读是插件约定，不是 Python 安全沙箱；`verify` 不执行插件附检。
- 孤儿副本只报告，不自动删除；卸载预检查不自动级联或移出插件。
- 本机原有参考库三条哈希警告已核对：Git 原始字节与登记值一致，本地仅因 Windows LF→CRLF 检出转换而不同。未改写这些参考资产来消除提示。
- 个性化的 Windows 启动器、运行副本与本地报告留在本机，不提交绝对路径或用户资料到公开仓库。
