# 内核可靠性第一轮（2026-09-16）

插件规则更新后，提供给 Agent 的说明必须同步；无法同步时应明确失败。这一轮保留原有插件格式和工作流，修复失败处理并加入只读检查。

## 已完成

- `audit` 将插件读取失败计入退出码；未知目标不再被当成“没有附检”。检查脚本返回值必须是含合法 level 与字符串 message 的列表，坏返回值按该插件错误报告，继续检查其他插件。
- 同步先在内存渲染全部目标，标记缺失、重复、顺序错误与注册表结构错误在写入前阻断。命令部署副本使用本次新生成的主本，不再读取旧主本。
- `verify` 只读检查 AGENTS 注入区、check 检查块、命令用法块、字段注册表插件段及技能部署副本。漂移或孤儿副本返回 1；不自动删除副本。
- `can-uninstall <id>` 列出依赖插件和命令 owner/consumes 引用，存在引用时阻断。它只预检查，不自动移出目录或级联卸载。
- 日志及热缓存支持已有插件声明中的 `todo` 类型。
- 补充同步所需字段的类型检查，避免渲染过程中因声明类型错误崩溃。

## 实际验证

运行：`python -B .meta/scripts/test_kernel_reliability.py`。这是针对已发现问题的小型回归集，不是模型/平台测试矩阵。样例在系统临时目录运行，不碰真实资料。

最初 9 个测试方法在旧代码上产生 11 个断言失败（包含子场景）；修复后通过。随后补充全部投影面的覆盖、手写区保留和字段类型错误检查，共 11 个测试方法。

还可运行：`python -B .meta/scripts/demo_kernel.py <仓库外的新目录>`。生成独立体验库、一个 meeting-guide 教学插件、虚构会议原文及六个场景的实际运行报告。目标目录已存在即拒绝，不覆盖资料。脚本只建立原始资料和机械演示，不代替 Agent 理解会议；代理页与笔记由 Agent 阅读规则后生成。

日常检查：`wiki_plugin_kernel.py verify` 检查规则投影；`pipeline.py verify` 检查数据区附检与派生索引。二者职责不同。

本机运行记录：11 个测试方法及六个机械体验场景均通过；根工程和参考实例的内核投影检查通过。参考实例数据检查无错误，但有三条原文哈希警告：已逐一核对 Git 中的原始字节与登记哈希一致，本地仅因 Windows 检出时 LF→CRLF 转换而不同；未改写参考资产或掩盖警告。另建体验库的实际会议整理检查无错误，有一条新笔记暂无入链的非阻断警告。

## 边界

- 先准备全部输出，再用临时文件逐个替换。可预见的渲染错误不会留下半同步；不承诺断电或替换途中发生系统故障时的跨文件原子性。发生此类故障后查看差异并重跑同步。
- `audit` 执行插件脚本；只读是插件契约，不是安全沙箱。`verify` 不执行插件脚本。
- 机械检查通过不代表模型永远正确理解规则。本轮体验为当前 Agent 的有指导演示，未声称完成跨 Harness 或冷启动独立验证。
- 不自动删除孤儿副本，不更改原始资料保护约定，不引入插件市场。
